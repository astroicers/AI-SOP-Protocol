# 不知情執行者探測:六道 gate 的前測 / 後測完整紀錄

> 這份是**資料**,不是決策。決策在 [ADR-034](adr/ADR-034-four-tier-marking-for-gate-pseudocode.md)。
> 之所以另存一檔:ADR 只該記結論與依據,12 次探測的原始計數與逐條歸因放在那裡會壓垮它。

## 方法

派**不知情執行者**——只給 `pipeline.md` 路徑與 artifacts,**不提任何 skill、不提任何 ADR**,
禁讀 `docs/` 與 `CHANGELOG.md`。情境做成最正常的樣子,**不針對已知缺陷調校**
(否則測的是「它會不會找到我已經知道的東西」,不是「它會找到什麼」)。

回報契約五項,其中**第 2 項與第 5 項是缺陷的實際來源**:

1. Gate 判定 + issues
2. **實際執行的每一步,包含判斷「不適用」而跳過的,並說明為什麼跳過**
3. YELLOW_FLAG 清單
4. checks 清單
5. **pseudocode 寫得不清楚或不確定怎麼執行的地方——要具體到行號與原文**

### 後測的可比性

- **同六個情境 repo**(未重建,原樣沿用)
- **派工單逐字相同**——從 session transcript 撈出前測的 Agent prompt 原文重派
- ⚠️ **唯一差異**:後測加了「不得在 ASP repo 執行 `git log`/`show`/`diff`」。
  前測時無此風險(標記 commit 尚不存在)。**這是一處已知的不對稱**,記錄在此。
- ⚠️ G5 的前測(#101)**完全沒有禁讀清單**(當時 ADR-034 尚不存在),後測有。
  G5 那一列的 6 → 10 因此比其他五道更不可比。

## 後測獨有的兩條實質發現

### 1. PR #112 的「已對齊」宣稱是假的(G1)

#112 寫「兩層的判定規則自 2026-08-18 起已對齊(皆大小寫不敏感)」。
**只對齊了大小寫,沒對齊比對模式:**

| 層 | 比對方式 |
|---|---|
| `.asp/checks/adr-draft.sh` L39 | `grep -qiE "${TABLE_RE}\bDraft\b"` —— **詞界子字串** |
| `pipeline.md` `evaluate_G1` | `adr_status == "draft"` —— **整串精確相等** |

拿該腳本自己 L13 文件化的合法格式當反例:`| 狀態 | Draft(待確認) |`
→ 後手 exit 1 blocker;pseudocode 得 `"draft(待確認)"` ≠ `"draft"` → **不 FAIL**。
**#112 自陳修掉的鐵則 fail-open 仍然開著。** 已於 PR #113 完成對齊(改為 `CONTAINS_WORD`)。

### 2. G3 執行者兩輪都拒絕背書

前測:「我不背書這個判定,也不會簽 pseudocode 要我輸出的那行證據。」
後測:「這是一個**有條件的 PASS**,而且我認為它不該讓人安心……**G3 沒有攔下它。**」

兩次都是在 pseudocode 明確要求輸出綠燈證據時,執行者選擇證據誠實。

## 可帶走的三條

1. **標記一個缺口不會讓缺口消失。** 這聽起來顯而易見,但 ADR-034 的整個診斷
   建立在相反的假設上(「約一半的缺陷是形式造成的幻覺」),而那個假設**只有靠實測才推翻得了**
   ——事前讀 23 條缺陷回報,它們看起來確實像幻覺。
2. **修正註解要寫完成式。** 用現在式描述已修好的 bug,下一個逐字執行者會去找它。
   兩位執行者各自踩到,兩次都寫成缺陷回報。
3. **一次「零行為變更」的形式改動,可以製造 10 個新缺陷。** 全部是註解,全部屬實。
   零行為變更保證的是**行為**不變,不保證**可讀性**不退步。
